# 임베디드/DDR 메모리 최적화

임베디드 환경(MicroBlaze 등)에서 모든 텐서/가중치 접근이 DDR을 거치도록 설정한 경우, 메모리 대역폭이 병목이 될 수 있습니다. 이 문서는 메모리 이동을 줄이기 위한 적용 사항과 추가 전략을 정리합니다.

## 현재 적용된 최적화

### 1. Conv+BN+SiLU 융합 (Fused Op)

**목적**: Conv 결과를 DDR에 한 번 쓰고, BN·SiLU를 위해 다시 읽는 왕복을 제거합니다.

**동작**:
- `conv2d_fused_bn_silu_forward()`: Conv 연산 후 중간 결과를 DDR에 쓰지 않고, 레지스터/로컬 버퍼에서 BN과 SiLU를 한 번에 적용한 뒤 **최종 결과만** DDR에 기록합니다.
- `bn` 인자가 `NULL`이면 Conv+SiLU만 수행(fused BN으로 bias에 이미 반영된 경우).

**적용 위치**:
- **Backbone / Head**: `yolov5n_infer.c`의 모든 Conv+BN+SiLU 구간
- **C3 블록**: `c3.c`의 cv1, cv2, cv3 (Conv → BN → SiLU → 출력)
- **SPPF 블록**: `sppf.c`의 cv1, cv2
- **Bottleneck 블록**: `bottleneck.c`의 conv1, conv2

**효과**: 레이어당 중간 특징맵 DDR 쓰기 1회 제거 → DDR 트래픽 및 병목 완화.

### 2. 연산 단위 메모리 접근 최소화

- **Conv2d**: `tensor_at_const`/`tensor_at` 제거, 포인터 순차 접근 및 1×1/3×3 전용 경로로 캐시 친화적 접근.
- **Batchnorm2d**: 채널별 `inv_std` 1회 계산, 순차 스캔.
- **Activation (SiLU)**: 인라인 시그모이드, 순차 포인터 접근.
- **Concat**: 채널 슬라이스 단위 `memcpy`로 복사 효율 극대화.
- **Pooling / Upsample**: 인덱스 계산 최소화, 블록 단위 쓰기.

## 추가 고려 사항

### 워크스페이스(임시 버퍼) 재사용

- **C3**: `c3_forward` 내부에서 `skip_output`, 필요 시 `bottleneck_temp` 등을 할당합니다. 호출 측에서 **고정 워크스페이스**를 넘기고, 가능하면 레이어 간에 같은 버퍼를 재사용하면 할당/해제 및 단편화가 줄어듭니다.
- **SPPF**: `workspace1`~`workspace3`와 `y1`/`y2`/`y4`/`x_copy` 등이 내부에서 할당됩니다. 최대 크기 워크스페이스를 한 번 할당해 두고 재사용하는 방식으로 바꾸면 DDR 할당 오버헤드가 감소합니다.
## buf_a / buf_b 워크스페이스 (역할과 병목)

### 왜 buf_a, buf_b를 쓰나?

- **역할**: 레이어 N의 **입력**과 **출력**을 담는 **두 개의 버퍼**만 두고, 매 레이어마다 “입력 버퍼 → 연산 → 출력 버퍼” 후 **포인터만 스왑**해서 다음 레이어로 넘깁니다.
- **목적**: 중간 레이어 결과를 전부 메모리에 쌓지 않고, **동시에 필요한 건 최대 2개**로 제한해 **피크 메모리**를 줄입니다. FPN에서 쓰는 일부 레이어만 `saved_features`에 복사해 두고, 나머지는 buf_a/buf_b에서 바로 다음 레이어로 넘깁니다.

### 병목이 되는 부분

1. **레이어마다 malloc/free**: 출력 shape가 레이어마다 달라서, 현재 코드는 매 레이어마다 `tensor_free(buf_b)` 후 `buf_b = tensor_create(...)`로 **새 크기로 재할당**합니다. 임베디드에서 이렇게 하면:
   - **할당/해제 오버헤드**와 **단편화**가 커질 수 있고,
   - DDR 쪽 allocator가 느리면 **병목**처럼 보일 수 있습니다.
2. **DDR 읽기/쓰기**: 레이어 출력을 buf_a 또는 buf_b(DDR)에 쓰고, 다음 레이어가 그걸 다시 읽는 것은 **구조상 필요**합니다. Conv·C3·SPPF 등은 입력과 출력 shape가 달라 **in-place로 대체할 수 없어**, 최소 “입력 1버퍼 + 출력 1버퍼”는 필요합니다.

### buf_a/buf_b 없이 할 수 있는지

- **완전 제거는 불가**: “현재 레이어 입력”과 “현재 레이어 출력”을 동시에 가져야 하므로, **최소 2개의 워크스페이스**는 필요합니다.
- **대신 할 수 있는 것**:
  - **Arena 기반 워크스페이스**: 추론 시작 시 arena 2개(또는 1개를 번갈아 리셋)를 만들고, buf_a/buf_b의 **메모리만** `arena_alloc`으로 받아서 `tensor_wrap`으로 감쌉니다. 레이어마다 `tensor_free` + `tensor_create` 대신 **arena_reset + arena_alloc**만 하면, **malloc/free 호출을 제거**해 할당 병목과 단편화를 줄일 수 있습니다.
  - **고정 2버퍼**: 두 버퍼를 “최대 shape 한 번 할당”으로 쓰는 방식은, YOLOv5n에서 최대 (512, 320, 320) 등으로 커져 **메모리 사용량이 매우 크기 때문에** 일반적으로 비추천입니다.

### Detect Head Conv

- `detect.c`의 `detect_convs`는 Conv+Bias만 사용(BN 없음). int8 전용으로 `conv2d_quant_forward` 사용. 융합 op은 BN이 있거나 SiLU만 붙는 경우 `conv2d_quant_bn_silu_forward`로 적용됩니다.

## 향후 확장 아이디어

임베디드 SoC(FPGA BRAM, 제한된 DDR 대역폭)를 더 활용하려면 아래를 검토할 수 있습니다.

| 전략 | 설명 |
|------|------|
| **BRAM 활용** | 자주 쓰는 작은 버퍼(예: 활성화 타일, 작은 특징맵)를 BRAM에 두고, DDR 접근 횟수 감소. |
| **Weight staging** | 현재 레이어/블록에 필요한 가중치만 작은 버퍼로 미리 복사한 뒤, 연산은 그 버퍼 기준으로 수행. DDR에서 반복적으로 큰 weight 블록을 읽는 비율 감소. |
| **Tiling** | 특징맵을 H/W 타일로 나누어 한 타일만 DDR↔로컬 버퍼로 옮기고, Conv 등 연산을 타일 단위로 수행. 메모리 풋프린트와 DDR 피크 대역폭 완화. |
| **Double buffering** | 다음 타일을 로드하는 동시에 현재 타일 연산을 수행해 메모리 대기 시간 숨기기. |

위 항목들은 플랫폼(메모리 맵, BRAM 크기, DMA 유무)에 따라 설계가 달라지므로, 타깃 보드가 정해진 뒤 `platform.c` 및 할당 전략과 함께 구체화하는 것이 좋습니다.

## 요약

- **적용됨**: Conv+BN+SiLU 융합으로 중간 DDR 쓰기 제거, 연산별 메모리 접근 최소화.
- **권장**: C3/SPPF 워크스페이스 고정·재사용으로 할당/해제 및 단편화 감소.
- **선택**: BRAM, weight staging, tiling, double buffering은 타깃 하드웨어에 맞춰 단계적으로 도입.
